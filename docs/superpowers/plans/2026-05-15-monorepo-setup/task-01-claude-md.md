# PTLand Plugins

Monorepo плагинов для Minecraft Paper 1.21.1 сезонного сервера. Язык: Kotlin. Текущий сезон: Лето.

## Tech Stack

- **Язык:** Kotlin 2.0.21
- **Сборка:** Gradle + Kotlin DSL (`build.gradle.kts`)
- **Платформа:** Paper 1.21.1
- **Тесты:** JUnit 5 + MockBukkit

## Структура проекта

```
ter-lib/        # Общие утилиты — загружается как Paper-плагин; другие плагины зависят от него
ter-climate/    # Температура, погода, урон от солнца, трансформация биомов
ter-lore/       # Фазы лора, команды /lore, метеорит, ивент-миры
ter-structures/ # Мультиблочные постройки (термометр, холодильник)
ter-items/      # Кастомные предметы: жаростойкая броня, ночная кровать, книги-чертежи
```

## Зоны ответственности плагинов

Перед добавлением кода — определи, в какой плагин он идёт:

| Механика | Плагин |
|----------|--------|
| Значение температуры, трансформация блоков биомов, урон от солнца, дождь | `ter-climate` |
| Команды `/lore`, фазы лора, метеорит, ивент-миры | `ter-lore` |
| Детект мультиблочных построек, термометр, холодильник | `ter-structures` |
| Кастомные рецепты крафта, кастомная броня, ночная кровать | `ter-items` |
| Утилита, нужная двум и более плагинам | `ter-lib` |

Если механика не вписывается ни в один — создай новый `ter-*` плагин.

## Взаимодействие между плагинами

Плагины общаются **только через Paper Events**. Никогда не импортировать классы другого плагина напрямую.

```kotlin
// Правильно: бросить кастомное событие
Bukkit.getPluginManager().callEvent(ChunkTemperatureChangeEvent(chunk, newTemp))

// Неправильно: прямой вызов метода другого плагина
terClimatePlugin.getTemperature(chunk)
```

Кастомные события определяются в плагине, которому принадлежат данные (события температуры — в `ter-climate`).

## ter-lib

`ter-lib` — это Paper-плагин (есть `plugin.yml`, загружается сервером первым).

В Gradle добавить в зависимости плагина: `compileOnly(project(":ter-lib"))`
В `plugin.yml` плагина добавить: `depend: [TerLib]`

Доступные утилиты:

| Класс | Назначение |
|-------|-----------|
| `ScreenEffects` | Тряска экрана, частицы, title для всех игроков |
| `CompassUtils` | Перенаправить все ненамагниченные компасы на координату |
| `MultiblockDetector` | Проверить, совпадают ли блоки вокруг триггера с паттерном |
| `CustomItemRegistry` | Тегировать и идентифицировать кастомные предметы через `PersistentDataContainer` |
| `RecipeLoader` | Загрузить рецепты крафта из YAML-конфига |
| `ConfigUtils` | Extension-функции для безопасного чтения конфигов |

## Конфигурация

Все числа, типы блоков, названия предметов, пороговые значения → в `config.yml` соответствующего плагина. Никаких захардкоженных значений в коде.

## Команды сборки

```bash
./gradlew build                  # собрать все плагины
./gradlew :ter-lib:test          # запустить тесты ter-lib
./gradlew :ter-climate:build     # собрать конкретный плагин
```

Готовые JAR-файлы: `<плагин>/build/libs/<плагин>-1.0-SNAPSHOT.jar`

## Стандарты кода

- Только Kotlin — никакого Java
- KISS: никаких абстракций "на будущее" — только то, что нужно сейчас
- Комментарии в коде — только если причина неочевидна
- Идентификаторы на английском; русский допустим в конфигах и комментариях
- Все новые плагины начинаются с префикса `ter-`
