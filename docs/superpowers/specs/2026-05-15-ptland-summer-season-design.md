# PTLand — Summer Season Plugin Design

**Date:** 2026-05-15
**Author:** Terenty
**Status:** Approved

---

## Overview

Сезонный Minecraft-сервер на Paper 1.21.1. Первый сезон — Лето. Мир постепенно деградирует из-за глобального потепления. Цель игроков — построить холодильники чтобы замедлить и обратить потепление.

---

## Стек технологий

- **Платформа:** Paper 1.21.1
- **Язык:** Kotlin
- **Сборка:** Gradle + Kotlin DSL (`build.gradle.kts`)
- **Версии:** централизованы в `gradle.properties`

---

## Структура репозитория

```
ptland-plugins/
├── settings.gradle.kts        # перечисляет все subprojects
├── build.gradle.kts           # общие зависимости для всех плагинов
├── gradle.properties          # версии: kotlin, paper API, плагинов
│
├── ter-lib/                   # общие утилиты (не плагин, Kotlin-библиотека)
│   └── build.gradle.kts
│
├── ter-climate/               # температура, погода, урон от солнца, трансформация биомов
│   └── build.gradle.kts
│
├── ter-lore/                  # фазы лора, метеорит, команды /lore, ивент-миры
│   └── build.gradle.kts
│
├── ter-structures/            # мультиблочные постройки: термометр, холодильник
│   └── build.gradle.kts
│
└── ter-items/                 # кастомная броня, кровать-дневной скип, книги-чертежи
    └── build.gradle.kts
```

`ter-lib` — не Minecraft-плагин (нет `plugin.yml`). Подключается через `implementation(project(":ter-lib"))`.

## Плагины — зоны ответственности

### ter-lib
Общий код для двух и более плагинов:
- **ScreenEffects** — тряска экрана, title/subtitle, частицы для игроков
- **CompassUtils** — обновить все компасы на координату (пропустить намагниченные лодстоуном)
- **MultiblockDetector** — универсальный детектор 3D-паттернов блоков
- **CustomItemRegistry** — регистрация и поиск кастомных предметов через `PersistentDataContainer`
- **RecipeLoader** — загрузка рецептов крафта из YAML и регистрация в Paper
- **ConfigUtils** — чтение конфигов с дефолтами и валидацией

### ter-climate
Ядро сезона — температурная система:
- **Глобальная температура:** начинается с 30°C, растёт автоматически
- **Скорость:** в градусах за реальный месяц (дефолт: 50°/месяц)
- **Температура чанка:** каждый чанк хранит свою температуру; ленивое обновление для выгруженных чанков
- **Хранение:** `Map<ChunkCoordinate, ChunkData>` где `ChunkData` содержит температуру, модификатор скорости и время последнего обновления
- **Обновление:** происходит не каждый тик, а раз в ~14.4 часа (при скорости 50°/месяц)
- **Пороги температуры:**
  - `30°C` — старт, солнце немедленно поджигает игроков без брони
  - `40°C` — начало трансформации: трава → грязь/гравий, листья желтеют; посевы на солнце сохнут
  - `50°C` — дожди в 3 раза реже
  - `55°C` — листья опадают, реки высыхают
  - `65°C` — дожди исчезают полностью
  - `70°C` — дерево медленно превращается в угольные блоки
  - `200°C` — максимум
  - `20°C` — минимум (нормальный мир, блоки восстанавливаются)
- **Бросает события:** `ChunkTemperatureChangeEvent`, `GlobalTemperatureChangeEvent`

### ter-lore
Лор и администрирование сезона:
- **Фазы лора:**
  - Фаза 0: старт сезона
  - Фаза 1: первый термометр построен (триггер — `StructureActivatedEvent`)
- **Метеорит** (`/lore meteor <x> <y> <z>`):
  - Эффекты для всех игроков: тряска экрана, частицы, звуки через `ter-lib`
  - Генерация кратера в указанных координатах
  - Сундук в центре кратера с книгой-чертежом термометра
  - Все ненамагниченные компасы начинают указывать на метеорит через `ter-lib`
- **Ивент-мир** (`/lore event fridge <player>`):
  - Телепортирует игрока в отдельный мир-испытание
  - По завершении: выдаёт книгу-чертёж холодильника, телепортирует обратно
- **Команды** (только для администраторов):
  ```
  /lore phase                   — текущая фаза
  /lore settemp <value>         — установить глобальную температуру
  /lore speedtemp set <value>   — скорость температуры (°/месяц)
  /lore transspeed set <value>  — скорость трансформации блоков
  /lore meteor <x> <y> <z>      — запустить метеорит
  /lore event fridge <player>   — ивент холодильника игроку
  ```
- Реализация команд через Paper Brigadier API (Paper 1.21+)

### ter-structures
Мультиблочные постройки:
- **Детект:** при переключении рычага (`PlayerInteractEvent`) сканирует паттерн вокруг через `MultiblockDetector` из `ter-lib`
- **Бросает события:** `StructureActivatedEvent`, `StructureDeactivatedEvent`

**Глобальный термометр** (чертёж из метеоритного сундука):
- Мультиблочная структура из незерских кирпичей с рычагом как триггером
- Показывает температуру незатронутого чанка (без локального модификатора)
- Визуальный индикатор: бетонный блок меняет цвет по температуре
- Градиент: `GREEN → LIME → YELLOW → ORANGE → RED → BROWN → BLACK` (20°C → 200°C)

**Локальный термометр** (чертёж и ядро из метеоритного сундука):
- Та же механика, но показывает температуру текущего чанка (с модификатором)

**Локальный холодильник** (чертёж из ивента `/lore event fridge`):
- Уменьшает скорость температуры на 30°/месяц во всех чанках в радиусе 30 блоков
- Несколько холодильников складываются

**Глобальный холодильник** (чертёж — будет добавлен позже):
- Гигантская постройка
- Уменьшает глобальную скорость температуры до -200°/месяц

### ter-items
Кастомные предметы:
- **Жаростойкая броня** — защищает от урона солнца; рецепт из `config.yml`
- **Ночная кровать** (чёрная кровать с кастомным рецептом) — пропускает день
  - Использует геймрул `playersSleepingPercentage`
  - Реализована через `PlayerBedEnterEvent` + `world.setTime()`
- **Книги-чертежи** — кастомные `WrittenBook` с текстом из конфига; выдаются через `ter-lore`

## Взаимодействие между плагинами

Плагины общаются **только через Paper Events**. Никаких прямых вызовов методов между плагинами.

```
ter-climate  →  ChunkTemperatureChangeEvent   →  ter-structures (обновить бетон термометра)
ter-structures → StructureActivatedEvent      →  ter-lore (переход на фазу 1)
ter-lore     →  (вызывает ter-lib утилиты напрямую, т.к. lib — зависимость, не плагин)
```

## Конфигурация

Все числовые пороги, рецепты, тексты хранятся в `config.yml` каждого плагина. Ничего не хардкодится в коде.

**ter-climate/config.yml (пример):**
```yaml
temperature:
  initial: 30.0
  speed: 50.0
  min: 20.0
  max: 200.0

thresholds:
  transformation-start: 40.0
  leaves-fall: 55.0
  wood-burns: 70.0
  rain-rare: 50.0
  rain-none: 65.0

transformation:
  speed: 10        # блоков за тик при трансформации
```

**ter-items/config.yml (пример):**
```yaml
recipes:
  heat_armor_helmet:
    result: LEATHER_HELMET
    shape:
      - "GGG"
      - "G G"
    ingredients:
      G: GLASS
```

## Стандарты кода

- **Kotlin везде** — никакого Java-кода в плагинах
- **KISS** — никаких абстракций "на будущее"; только то, что нужно сейчас
- **Разделение:** новая механика → сначала вопрос "в какой плагин?"
- **Зависимости:** предпочитать Paper API; сторонняя библиотека только если Paper не справляется
- **Конфиги:** все числа, тексты, материалы — в `config.yml`, не в коде
- **Комментарии:** только если причина неочевидна; не описывать что делает код
- **Имена:** на английском; комментарии и конфиги можно на русском
